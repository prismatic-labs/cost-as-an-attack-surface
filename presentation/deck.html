3 · Volume vs. leverage

Agentic security has to count the work inside each request

Traditional web app

  • Requests per second
  • Network bandwidth
  • Server uptime (5xx)

AI agent with tools

  • Model calls per request
  • Paid tool calls
  • Growing chat history

4 · The basics

Every model call is billed for everything the agent has read up to that point

A token is a piece of text. The demo's request is 16 tokens:

SummarisetheoperationsnoteDOC-14andnameonefollow-upcheck.

Each model call reads the whole context, everything that came before, then writes a reply:

Call 1 prompt→reply Call 2 promptreplytwo tool results→replyreads 7× as much
Read: billed as inputWritten: billed as output, which costs more

Prompt caching can bill the re-read part at a discount, and some agents trim their history.

5 · The attack surface

A document the agent reads can keep its loop of model and tool calls going

The agent loop: these steps repeat until the model decides it can answer

user request→ agent→ model→ tools→ history grows↻
tampered note (DOC-14)↗ read by tool, added to history, obeyed on the next step

Every turn of the loop re-reads the full history and bills you again.

13 · Detection gap

Traffic and error dashboards stay green because the attacker never sends the agent a request

Signal Volume attack (DDoS) ? Volume attack (classic DDoS): Flooding a server with thousands of requests per second until bandwidth or CPU runs out and the site crashes. Agentic Denial of Wallet ? Agentic Denial of Wallet: Planting instructions in data an AI agent reads so a single normal user request triggers dozens of expensive model and tool calls.
Attacker trafficThousands of requests/secNo requests to the agent (they edit a document, and a normal user's request does the rest)
What runs outBandwidth, CPU, connectionsAPI budget and token quotas

21 · Defence in depth

Production defence takes five layers, from document access to graceful partial answers

  1. Access & tool scope: who edits documents, which tools the agent can call
  2. Layered budgets: per-run limits backed by an account cap
  3. Document attribution: log which file drove the spend
  4. Pre-call guard: check budget before each model or tool call runs
  5. Partial answers: stop one runaway run, not the whole service

23 · Take-home worksheet

Five questions to check if your own agent can stop a runaway loop before the bill arrives

  1. Do we measure tokens, tool calls, and time for a single run?
  2. Can we trace spend to the user, agent, tool, and source document?
  3. Can we block the next call during the run, before the monthly bill?
  4. Will alerts fire when traffic is 1 request (HTTP 200) but tokens spike 100×?
  5. Can we stop one runaway run without killing a shared API key?

24 · Takeaway

In agentic AI, cost is a security boundary

1 · The threat

Untrusted text can trap an agent in a snowballing token loop.

2 · The trap

An iteration limit is not a budget, and a budget fitted to yesterday's tasks breaks tomorrow's.

3 · The fix

Layer a repeat check, a call budget and a size limit, with headroom, over a hard ceiling.
